# PeopleOps Control — portfolio specification

Build a runnable HR/payroll reconciliation project for the Harel HR Data Developer opening. This is an independent portfolio with synthetic data, not a Harel system. Demonstrate Python/Pandas, SQL, ETL operations, Excel automation and APIs without relying on paid services.

## Public interfaces
- `PeopleOpsService(data_dir: Path)` owns local SQLite storage. `run(period: str, scenario: str = 'review', employees: list[dict] | None = None) -> dict` processes a month. `dashboard(period: str | None = None) -> dict` returns the latest run, runs, metrics, departments, findings, records and sources. `get_run(run_id: str) -> dict | None` returns a run with its evidence. All returned values are JSON serializable.
- Period is YYYY-MM. Supported fixture scenarios: `clean`, `review`, `corrected`. Default demonstration month is 2026-09. The sample covers three months, 72 synthetic employees and six departments. IDs such as EMP-001 never represent real people.
- Money is stored as integer agorot (ILS cents). Attendance is stored as integer minutes. A documented simplified reconciliation rule, not statutory Israeli payroll: base salary + overtime minutes * hourly salary * 1.25 / 60, rounded half up. No tax, benefits or actual payroll payment.
- A source checksum plus period and rule version identifies a run. Identical inputs reuse the same run, without duplicate facts. Changed inputs create a new immutable run. Active monthly publication changes only when the run has no critical findings. Single-writer protection covers concurrent runs.
- Quality checks: duplicate source keys, unknown employee, missing attendance or payroll, negative/invalid amounts, inactive employee payment, gross difference greater than ILS 100, overtime over 30 hours. Critical defects block publication; warnings remain reviewable. Quarantine invalid rows, record usable rows, and preserve the prior published month after a blocked attempt. Decimal-safe calculations; explicit ownership and remediation for findings.
- Dashboard schema: `period`, `run` (id, period, scenario, status, started_at, duration_ms, source_hash, input_rows, accepted_rows, rejected_rows, critical_count, warning_count, reused), `metrics` (headcount, gross_cents, expected_cents, variance_cents, overtime_minutes, quality_score, published_run_id), `departments` (name, headcount, gross_cents, variance_cents), `findings` (id, employee_id, employee_name, department, rule, severity, message, owner, remediation, impact_cents), `records` (employee_id, employee_name, department, expected_cents, gross_cents, variance_cents, overtime_minutes, status), `runs`, `sources` (name, type, rows, status). Keep count names consistent.
- FastAPI serves the local demo, `POST /api/runs` with period/scenario, `GET /api/dashboard?period=`, `GET /api/runs/{id}`, `GET /api/runs/{id}/report`, `GET /api/health`, `GET /mock/hr/employees?page=1&page_size=25`. Optional HR HTTP adapter demonstrates timeouts, pagination, bounded retries, schema validation and no credential logging.
- Excel evidence pack contains Summary, Reconciliation, Exceptions, Lineage sheets with frozen headers, filters, money formatting, explicit synthetic-data and publication status. Reports use immutable run IDs and escape spreadsheet formulas in source text.
- CLI supports running a month and starting the demo; a scheduled monthly command uses the same pipeline. No ChatGPT reminders. Scheduled runs default to clean.
- SQL Server deliverables: executable schema, indexed facts, run audit and quality findings, a transactional idempotent publish procedure, complex reconciliation/department queries using CTEs/window functions, and optimization notes. Optional Python pyodbc adapter publishes a reviewed local run using parameterized inserts in a transaction. SQL Server execution must be reported unverified if no server is available.
- UI: polished responsive local control-room interface, accessible keyboard controls, period/scenario selection, real pipeline trigger, rule/severity filter, searchable employee reconciliation, run history and Excel download. Clearly distinguish blocked/reviewed/published and show synthetic-data notice.
- Deliver documentation: quick start, architecture, data contracts, operations runbook, business rules, interview walkthrough, Hebrew application paragraph and job requirement mapping. Include meaningful behavior tests and CI. Do not claim production readiness or real employer data.

## Approved test boundaries
The user approved the pipeline public service, HTTP endpoints/HR extraction and Excel output. Test financial worked examples, idempotent reruns, corrected inputs, critical blocking with last-good publication, paginated API recovery and exported workbook values. Browser smoke remains a separate execution limit when the environment cannot run a browser.
